# rs-du: анализатор диска + чистильщик кешей

**Статус:** этап 1 работает на живом диске (1,5 млн записей за ~2–3 с). Чистильщик (`--clean`, `--apply`) прошёл одну чистку на живом ПК. Дубликаты сделаны. Движок чистки лежит в `winrust-common` (`common/src/clean.rs`): rs-du показывает его в консоли, WinRust Disk (`wiztree --clean`) в окне.

Показывает за секунды, что занимает место на NTFS-диске, и помогает освободить его.

## Важное уточнение
Индекс `rust-search` хранит только `parent + name` (см. `Ent` в `rust-search/src/main.rs`), **размеров в нём нет**.
Поэтому rs-du читает MFT сам и берёт размер из атрибута `$DATA` (и `$FILE_NAME`) каждой записи.
Код обхода MFT берём из `rust-search` как образец, индекс не меняем.

## Функционал

### 1. Анализ (этап 1)
- `rs-du [диск]`: проход по MFT, размеры суммируются вверх по дереву `parent`.
- Вывод: топ-N папок и файлов по размеру, глубина дерева настраивается (`--depth`, `--top`).
- Считает реальный размер на диске (allocated), а не только логический. Флаг `--logical` переключает.
- Учитывает hardlink (один файл считается один раз), не заходит в junction и symlink.
- Вывод в консоль; `--json` для скриптов.
- Цель: диск на миллион файлов за секунды, а не минуты.

### 2. Чистильщик кешей (этап 2, `rs-du --clean`)
- Знает типовые места: `target` (Rust), `node_modules`, кеши cargo/npm/pip/nuget, `%TEMP%`, кеши браузеров, `$Recycle.Bin`.
- Режим по умолчанию только показывает, сколько можно освободить. Удаление только с `--apply`.
- Для проектов (`target`, `node_modules`) удаляет только если рядом лежит `Cargo.toml` / `package.json`.
- Перед удалением пишет список в лог для проверки; в корзину не кладёт (кеши пересоздаются).
- Не трогает системные папки и файлы, открытые процессами.

#### Чистка для обычного пользователя (`src/clean.rs`)
Каждый пункт: понятное название, пояснение и цвет риска.
- **Безопасно** (зелёное): Temp, отчёты об ошибках и дампы, кеш обновлений Windows, INetCache.
- **Можно удалить** (жёлтое, пересоздастся): кеш Chrome/Edge/Яндекс/Brave/Firefox (пароли и история не трогаются), Telegram, Discord, Teams, VS Code, шейдеры NVIDIA/AMD/DirectX, Steam, кеши разработчика, `target`/`node_modules`.
- **По выбору** (красное): корзина, `Windows.old`, старые установщики и архивы в «Загрузках» (>90 дней), большие забытые видео/архивы (>1 ГБ, не тронуты >180 дней, только в папках пользователя, не облако и не AppData).
- `target`/`node_modules` берутся только если сама папка и её дочерние (release, debug...) не менялись 30 дней. Пункты меньше 1 МБ не показываются.
- Режимы: `--clean` только список; `--clean --apply` зелёное+жёлтое; `--apply --safe` только зелёное; `--apply --all` всё; `--ask` нумерованный список и выбор (Enter, `a`, `n`, номера красных).
- Красные файлы из «Загрузок» и больших файлов не удаляются, а уходят в карантин `X:\.rs-du-quarantine` на 30 дней. Список того, что в карантине, хранится в `Program Files\WinRust\quarantine-X.tsv` (общий для rs-du и WinRust Disk, писать туда может только администратор; старый список рядом с `rs-du.exe` переносится туда сам). `rs-du --restore` возвращает, `rs-du --purge` освобождает место сразу.
- Без буквы диска чистка идёт по всем несъёмным дискам (`rs-du --clean`), с буквой только по нему (`rs-du D: --clean`).
- Файлы программ и игр не трогаются: вне папок пользователя (Загрузки, Рабочий стол, Документы, Видео, Музыка, Изображения) файл, рядом с которым или выше лежит `.exe`/`.dll` (или папка `Binaries`/`Engine`), считается частью программы. Временные файлы моложе двух часов остаются (установщик может ещё работать).
- Не сделано: определение остатков удалённых программ, точка восстановления (вместо неё карантин).

### 3. Дубликаты (этап 3)
- Файлы от 64 МБ в папках пользователя на всех дисках: группировка по размеру (из MFT, бесплатно), затем сравнение байт в байт (до первого различия).
- Остаётся самая старая копия, остальные предлагаются красными пунктами и уходят в карантин. Облачные заглушки (OneDrive и т. п.) не читаются.

## Чего не делаем
- Не-NTFS диски (как и в rust-search, пропускаются).
- Фоновая служба и расписание (может быть позже).
- Отдельный GUI в rs-du: окно чистки живёт в WinRust Disk.

## Права
Чтение MFT требует администратора (как rust-search).

## План
1. Читатель MFT с размерами + агрегация + вывод топа.
2. Замер на реальном диске, запись результата здесь.
3. Чистильщик.
4. Дубликаты.
5. Запись в `plugin-launcher` (карточка, `payload.txt`).
